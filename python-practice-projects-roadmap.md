## Challenge Rules

- No tutorials while implementing.
- No AI-generated complete solutions.
- Documentation is allowed.
- Search specific errors, not entire solutions.
- Write your own functions.
- Refactor after the first working version.
- Write tests for critical logic.
- Commit each milestone.

## Evaluation Score

| Category | Score |
|---|---:|
| Correct functionality | 20 |
| Code structure | 15 |
| Python concepts | 15 |
| Error handling | 10 |
| Edge cases | 10 |
| Testing | 15 |
| Readability & maintainability | 10 |
| Git usage | 5 |
| **Total** | **100** |

### Score interpretation

- **Below 50:** Fundamental gaps
- **50–64:** Beginner
- **65–74:** Developing intermediate
- **75–84:** Intermediate
- **85–94:** Strong intermediate / approaching advanced
- **95–100:** Excellent execution for the project's scope

*Scores must be interpreted relative to project complexity. A high score on a calculator does not equate to a high score on an API.*

## Suggested Workflow

1. Read the project requirements.
2. Design the solution before coding.
3. Implement without following a tutorial.
4. Test normal inputs, invalid inputs, and edge cases.
5. Refactor for readability and maintainability.
6. Write automated tests.
7. Commit the completed milestone.
8. Submit the code for review.

## Review Approach

Use AI as a code reviewer, not as the implementation author. Ask for review of:

- Logic flaws and edge cases
- Design and architecture
- Python idioms and readability
- Error handling
- Performance considerations
- Test coverage
- Maintainability

**Start with Project 1 — CLI Calculator.** Complete it independently, then get it reviewed before moving to Project 2.
